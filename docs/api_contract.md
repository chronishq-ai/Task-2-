# Core State Engine API Contract

## 1. Purpose

This document defines the communication interface between the **Core State Engine (Pod A)** and the other components of the Chronis architecture.

The Core State Engine maintains the current representation of a user's behavioral and emotional state. It receives incoming event signals, applies confidence-aware state updates, and returns an updated user state that can be used by the AI agent for reasoning and personalization.

---

# 2. Core State Engine Function Interface

The primary interface exposed by Pod A is:

```python
def update_state(
    current_state,
    event_signals
) -> updated_state:
    """
    Updates the user's behavioral state based on incoming event signals.
    """
```

### Inputs

- Current user state
- Incoming event signals
- Signal confidence scores

### Output

- Updated user state representation

---

# 3. Input Format

The State Engine receives:

- User identifier
- Current state values
- Incoming signals generated by the Event Interpretation Layer

### Example Input

```json
{
  "user_id": "user_001",
  "current_state": {
    "mood": 7,
    "focus": 8,
    "stress": 3,
    "confidence": 6,
    "trust": 8,
    "motivation": 7,
    "social_engagement": 5
  },
  "signals": {
    "stress": {
      "value": 8,
      "confidence": 0.9
    },
    "mood": {
      "value": 3,
      "confidence": 0.8
    }
  }
}
```

---

# 4. Signal Definition

Each incoming signal consists of two components.

| Field | Description |
|--------|-------------|
| `value` | Suggested target state value (0–10) |
| `confidence` | Reliability of the generated signal (0–1) |

### Example

```json
{
  "stress": {
    "value": 8,
    "confidence": 0.9
  }
}
```

### Interpretation

The system believes the user's stress should move toward **8** and is **90% confident** in this interpretation.

---

# 5. Output Format

After processing the incoming signals, the Core State Engine returns the updated user state.

### Example Output

```json
{
  "user_id": "user_001",
  "updated_state": {
    "mood": 5.2,
    "focus": 8,
    "stress": 6.15,
    "confidence": 6,
    "trust": 8,
    "motivation": 7,
    "social_engagement": 5
  }
}
```

---

# 6. State Update Logic

The Core State Engine performs confidence-weighted state transitions.

### Effective Speed

```text
effective_speed =
variable_speed × signal_confidence
```

### State Update Formula

```text
new_state =
current_state +
effective_speed ×
(evidence_value - current_state)
```

### Example

**Current Stress**

```text
3
```

**Incoming Signal**

```text
Stress = 8
Confidence = 0.9
```

**Variable Speed**

```text
0.7
```

**Effective Influence**

```text
0.7 × 0.9 = 0.63
```

The state moves toward the new evidence gradually instead of changing instantly.

# 8. Error Handling

The Core State Engine validates all incoming data before applying updates.

Validation rules include:

- State values must remain within the range **0–10**
- Confidence scores must remain within the range **0–1**
- Variable update speeds must remain within the range **0–1**
- Unknown state variables should be ignored safely or logged
- Invalid payloads should return structured validation errors

---
